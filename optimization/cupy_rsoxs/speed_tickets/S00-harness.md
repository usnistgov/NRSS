# S00 · Establish the paired timing and verification controls

**Deliverable.** A local agent can run one equivalent current/candidate workload, see which implementation ran, measure a synchronized result, and spot a wrong image without timing the comparison. This ticket gates speed rankings.

The supplied `tests/validation/dev/cupy_rsoxs_optimization/run_speed_tickets.py` already implements repeated workers, alternating pairs, uninstrumented and instrumented cases, energy presets, exact-key checks, failure propagation, same-output controls, unique results and raw JSON. Start with the three runnable controls in [MEASUREMENTS.md](MEASUREMENTS.md). The main optimization matrix remains the fixture/worker implementation. Its CLI rejects an empty segment list, while its worker JSON already accepts one. Run A/A first on each GPU class used for decisions.

1. Add a development-only way to select each candidate in the worker, plus an **actual execution report** with selected route, fallback reason, number/type/shape of FFTs, basis builds, distinct energies, compute tile count/size and final tile length. Route evidence comes from the operation executed. Logging the requested option alone can hide a fallback. Put counters and CUDA-event instrumentation behind a diagnostics flag where they carry measurable cost. Preserve the default result and public timing boundary.
2. Extend the separate accuracy pass of the runner to run the same arms on a deterministic case, retrieve raw values and coordinates before `release_runtime()`, and compare masks and intensities outside the clock. Support first/middle/last energies for quick screening and all energies/pixels for promotion. Support dataset channels and their q coordinates for reduced layouts. Check mismatches in shapes and infinities explicitly. For the new multi-energy method include a small generic fixture with varying `v` and `S`, tilted directors, distinct complex material spectra and a weak-contrast energy. This complements the vendored CoreShell fixture.
3. Add genuine fused-stage event ranges, basis-build and per-energy/tile timings, and separately instrument reduction, D2H transfer, and synchronization. A candidate that launches on an auxiliary stream must join that stream before the result is reported complete. Leave the primary pass free of events and memory observers. In a diagnostic pass include device name/UUID, driver/runtime/cuFFT and CuPy versions, input/result residency, dtype and actual output shape. Report time/energy, time per scan and primary ratios.
4. Add an opt-in prepared-geometry timing mode only for candidates that reuse data across separate calls. Keep the current fresh-object baseline. For S04 allow fixed XY/voxel size with independently specified material Z and optional transform Z, and expose valid columns, distinct endpoints and distinct global z planes. For the current geometry use the backend-generated indices as authority. Add `WindowingType` and `RotMask` switches for targeted checks.
5. Reuse the separate speed/memory passes of `run_comprehensive_backend_comparison.py`. Its current subprocess parameter is `gpu_device`. Six old rechecks use `gpu_index`. Port a historical script only if actually needed. Use new output directories or disable cached results while revising a candidate. The stock timing worker can serialize an error and return process status zero. The supplied runner treats its JSON `status` as authoritative as well.

**Finish.** Show one successful A/A report, one counted intended route and one deliberately failed comparison rejected by the runner on a tiny case. Save an instrumented small/medium baseline split for A2, B, C+D, E and output work. Record the speed ceiling implied by the time available to change. Candidate development can start as soon as its required controls work. A full physics report is due at S07.

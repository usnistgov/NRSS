# Measuring speed on existing workflows

Run in the locally configured NRSS GPU environment from the checkout root. Pin one available GPU and keep input residency distinct from result residency. The commands below assume GPU 0 if `CUDA_VISIBLE_DEVICES` is unset. Use `--gpu` for an allocated index or UUID. The launcher uses `[start, increment, end]` degrees for `EAngleRotation`. The 12-angle workload is [0,15,165], the 34-angle workload [0,5,165], and one E direction [0,0,0].

```bash
RUN=tests/validation/dev/cupy_rsoxs_optimization/run_speed_tickets.py
python "$RUN" --list
python "$RUN" --case one --path direct_polarization --aa --repeats 3
python "$RUN" --case angles --path tensor_coeff --aa --repeats 3
python "$RUN" --case energy20 --path tensor_coeff --resident host --stages --repeats 1
```

The launcher reads the three vendored material tables, checks all requested keys, submits the `BenchmarkCase` JSON protocol and checks the worker's status as well as the process exit code. `--dry-run` prints the complete configuration without GPU work. With no B arm it measures the incumbent. `--aa` measures two identical arms. Use `--baseline-root PATH --candidate-root PATH` for two checkouts, or `--candidate-options '…'` for a registered backend option in one checkout. Options are proposed and registered by their implementation ticket. To compare two code revisions with an opt-in candidate, give both checkout paths **and** its option. Both arms use the same worker and import NRSS and fixture data from their respective checkouts. The saved `plan.json` records the host, the checkout commits, the CuPy backend file hashes and the options for each arm.

**Timing contract.** Primary seconds start at `Morphology(...)` and end after the synchronized `run(return_xarray=False)`. Input generation precedes the clock. Planning, index packing, optical coefficient assembly, FFT workspace setup, all stream joins, host/device output delivery for the selected layout, and any per-run basis build belong inside. Preserve the public stateless workflow. Current workers create and release a new morphology during each warm-up. Release drains memory pools and the cuFFT plan cache. One warm-up therefore measures a fresh object in a warmed process. Label any separate prepared/reused run, show setup and steady-state seconds, and recompute scattering on every repetition. Record the amortization count if persistent reuse is claimed.

The default launch uses no profiling events. `--stages` records the A1/A2/B/C/D/E/F split, a CUDA-event range for C+D, per-energy ranges, reduction, transfer on the copy stream, and host waits. F times result-object assembly. Overlapping ranges can count the same work. Collect one instrumented pass per condition and use uninstrumented primary seconds for ranking. Stage reports include GPU and library versions, shape and dtype, executed routes, FFT counts by method/shape/dtype, and the actual compute-tile lengths. In the incumbent each energy is its own compute tile. Use `--expect-route ROUTE` with `--stages` to require the reported route for B or a lone A arm. The pinned pre-S00 baseline provides its original stage split. Run detailed diagnostics in the checkout with S00 instrumentation. Time new basis builds, fused kernels and multi-energy tiles at their launch sites. A prepared-geometry lane is relevant when a candidate retains geometry across calls.

Small = 32 × 512 × 512 at 2.5 nm. Medium = 64 × 1024 × 1024 at 1.25 nm. The existing ladder scales all dimensions at a fixed physical size. Float32 morphology, complex64 incumbent fields, full z, `enum_contract`, identical materials and E-angle weights are the default. Host detector result, output chunk 1, window off and rotation mask off are the controls. Change one dimension at a time. A reduced-output or ROI benefit needs a comparator delivering the same product. `--layout i_a` returns I and A. Include `integrated` or `i_para_i_perp` where used by a candidate. Test device output separately if it changes the conclusion.

**Evidence per comparison.** Alternate A/B then B/A in isolated workers on the same idle GPU. Use 3 pairs to screen, 5 to decide a winner, and more only when observed variability can change the decision. Save raw seconds, median paired speedup `T_A / T_B`, number of favorable pairs, energies/s, critical conditions, device model/driver/CuPy/cuFFT versions and the selected routes. A/A estimates the ordinary variation. A proposed decision rule is a primary gain exceeding both 5% and twice the median absolute A/A fractional deviation on the target case, with at least 4 of 5 favorable pairs. Recheck protected single-energy workloads if they slow by more than 3% or the local noise floor, whichever is larger. Record exceptions or make a workload-specific recommendation. Speed thresholds are campaign choices, not historical repository policy.

Use `--memory` to run the external `cupy_gpu_mem_observer.py` in a separate pass for finalists. The worker JSON records the observer interval, peak delta and free VRAM at launch and links to the trace. Polling can miss short-lived allocations. Record workspace size and peak live arrays for a near-capacity case. Record an OOM as a capacity result with the same inputs for the successful arm. It cannot yield a paired speed ratio.

**Accuracy while iterating.** Use `--accuracy screen` for first/middle/last energies or `--accuracy full` for every energy. Each arm saves values and coordinates before runtime release. The comparison requires matching dimensions, coordinates and finite masks and reports absolute differences and normalized L2 by energy and channel. Both tolerances default to zero for controls. Use `--accuracy-rtol` and `--accuracy-atol` for calibrated comparisons. The relative term uses the reference peak for the maximum error and the reference L2 norm for the L2 error. The absolute term supplies a bound for dark panels. `--fixture generic` gives a small asymmetric two-material Euler morphology with varying volume fractions and order, tilted directors, distinct spectra and a weak-contrast middle energy. Include a sector or anisotropy observable if rotation or reduction changes. The full pre-push criteria are in [S07](S07-promotion.md).

With `--stages --geometry`, detector demand is counted after timing from the backend's own indices and unioned over the requested scan. `--shape-label medium --material-z 32` changes material depth at fixed XY and voxel size, with the CoreShell sphere centered to fit the modified depth. `--transform-z` probes geometry on a specified diagnostic grid while the incumbent simulation still uses its configured transform. Use `--windowing-type 1` and `--rot-mask 1` to exercise the window and rotation mask.

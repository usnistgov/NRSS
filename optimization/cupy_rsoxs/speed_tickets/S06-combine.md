# S06 · Combine measured winners and set dispatch boundaries

Take the best matched incumbent and each candidate that passed its screen. Measure each winner alone against the incumbent, then the proposed combination on the same GPU and output. Improvements in memory traffic, FFT count and rotation can overlap. Use measured combined wall time for decisions.

1. For both current execution paths, cover `one` and `angles` and the 12-angle workflow. Use `energy20` and `energy101` for the candidate that reuses optical-independent fields. Compare the best existing path as well as the same-path incumbent. Check small/device first. Confirm on medium/host-prewarmed, on medium/device and on the 128 × 1024 × 1024 case if the affected algorithm depends on z depth and both arms fit. Select rather than multiply cases across every knob.
2. For a detector-specific implementation, include the full detector. For a reduced product, use the same reduction, q-grid mode and output residency in both arms. For an energy optimization, measure a single-energy fallback and first use of the actual dispatcher. If an advertised result depends on prepared reuse, provide fresh-object and retained-plan numbers. Where available, run one existing local fitting or multi-energy workflow with its usual materials, energies and returned product, and document the settings.
3. Fit a conservative decision table using measured independent variables such as energy count, anisotropic/isotropic material count, angle family, shape and required modes per column. Check one held-out energy count or depth near the proposed switch. Record how many bytes and what FFT workspace each candidate needs. Prove fallback works before allocating an infeasible tile. Prefer an opt-in option where a crossover is unstable across hardware. Preserve borrowed inputs, repeated-run behavior, cleanup, user optical constants and energy ordering.
4. Repeat the final cases for five paired runs against the original incumbent and the present best working route. Add a separate observer pass and a spot check through the actual proposed user entry point. If a protected workflow regresses materially, narrow dispatch or leave the candidate opt-in and rerun the affected comparison. A slower candidate with a capacity benefit gets a capacity entry rather than a speed recommendation.

**Finish.** In [RESULTS.md](RESULTS.md) give target and protected case timings, actual selected/fallback counts, applicable GPU/cost envelope and the revision to run through S07. A combined win that fails output parity returns to its first failing ticket.

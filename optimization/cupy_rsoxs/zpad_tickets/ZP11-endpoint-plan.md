# ZP11 · Direct endpoint addressing across energies

**Priority 1 after profiling.** Hold the scalar fused projector and the current virtual FFT evaluator fixed. Change only how the padded path finds required Fourier bins. Compare three arms on identical XYZ calls. Attribute the cost of building each representation, evaluating any additional bins, and using it in projection.

1. **Current control.** The planner recursively appends and deduplicates IDs in each detector block per distinct energy, then globally sorts. The scalar projector performs two global lower-bound searches per valid 3D pixel. Instrument both independently. A low-risk comparison builds exact demand in bounded column blocks, then merges/deduplicates once per block or over sorted runs. Measure peak scratch as well as time.
2. **Per-column spans.** Use `first_z[column]`, a count and an exclusive prefix sum yielding `base[column]`. Position of an endpoint becomes `base[column] + (z - first_z[column])`. Store the Fourier rows in this order and add the exact logical DC stencil before computing offsets. On the 101-energy vesicle the entire contiguous span adds 64 positions out of 2,017,475 required. Those extra coefficients can be evaluated legally at their own bins. Every projector query must still resolve to the specified physical endpoint. The packed ordering can change memory coalescing across columns, so compare it with current z-major storage. Keep flattened arithmetic, offsets and stencil addressing 64-bit. Narrow only proven bounded *relative* indices.
3. **Reuse identical geometry.** The forward projector takes a rounded FP32 squared transverse radius, photon energy and axial grid as inputs for validity, bins and axial fraction. The border mask is a separate per-pixel rule. Compare in-register recomputation with a table keyed by the exact FP32 bits of radius squared on a fixed grid. The vesicle has 31,128 distinct valid radii for 412,705 touched columns. Two pixels can have equal radius and different polarization projectors and basis amplitudes. Only the radial part of geometry is shared. At 101 energies all-radius tables can still be large. Measure construction/hash/sort, lookup traffic and peak memory against a bounded energy tile or block. Start with a reusable per-run plan. Persistent plans require measured additional benefit, complete invalidation keys and lifetime accounting.

Internally sorted distinct energies allow a first/last *valid* energy per column or radius. Ewald support grows and the forward axial endpoint moves toward zero over increasing energy on a fixed grid in exact arithmetic. Test the actual FP32 implementation at borders and integer axial crossings. A column that enters only at a later energy gets its first supported bin there. Separate empty columns and DC-only cases. Preserve requested ordering during output. For gapped or wide scans, compare packed disjoint runs or the existing sparse implementation. A cost rule based on extra **basis bytes × field count**, active support and memory budget should choose the affordable path. The wide control's 5.06 million excess bins would be expensive.

**Tests and decision.** Against the incumbent and an independently enumerated tiny geometry, compare presence and lookup of *every requested* `(column,z)`, valid mask, z0/z1, fraction and DC positions. Exercise limit-of-support pixels, odd/even targets, duplicate physical bins, a single plane where eligible, identity, sparse energy spacing, wide gaps, and address values above 2³¹. Across inputs check the actual registered coordinate ordering, Hermitian reflection and repaired values. Time width 1 on 1/20/101 energies and the sphere at 4096/8192. Record construction, projection and end-to-end wins separately. Keep a scalar direct-address arm for ZP12 even if the wide-scan dispatcher selects the old route.

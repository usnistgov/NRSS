# ZP02 · Compute and time only the axial bins the detector uses

**Exit with** matched timings and memory measurements that identify a usable GPU implementation or its crossover. Start with the eligible float32 `compact_r2c` path and its energy-independent real material basis. Keep padding opt-in. Reuse the S04 prototype if present in a local checkout. The [S04 record](../speed_tickets/RESULTS.md) covers native depth only. The parent implements the current public default for one or more eligible energies.

1. **Compare two axial evaluators.** Compute a batched `rfft2` across occupied XY planes for each real basis field. Use a tiled GPU kernel to evaluate the length-N sum for the union of requested native bins. For integer `M=pN`, write `m=pj+r`. Multiply plane n by `exp(−2πirn/M)`, perform a length-N axial FFT, and gather j. Stage only demanded residues and reuse workspace, with the embedding phase applied to each final coefficient. The selected sum supports all M. Keep phase and gather storage bounded. Separately measure launch count, layout conversion, phases, cuFFT, gather and projection so the cost of batching is visible.
2. **Replace the dense endpoint planner in C.** [`_detector_endpoint_union`](../../../src/NRSS/backends/_cupy_energy_basis.py) allocates one Boolean per logical volume cell. The host `_detector_demand` in [the matrix harness](../../../tests/validation/dev/cupy_rsoxs_optimization/run_cupy_rsoxs_optimization_matrix.py) does likewise. Each mask alone costs 1 GiB at 1024³. Build endpoint IDs per transverse block from the two z indices at valid pixels across unique energies, plus the target-grid DC stencil. Deduplicate and reuse the mapping across energies, angles and bases. Count columns, unique endpoints, residues, basis FFTs and bytes. Avoid a logical-volume mask or field and a global N × endpoints phase table. Bound the union or process tiles if a long energy scan makes it dense. Include planning and any repeated work in measured totals.
3. **Keep occupied and logical shape explicit.** In [the runtime](../../../src/NRSS/backends/cupy_rsoxs.py) and [energy basis](../../../src/NRSS/backends/_cupy_energy_basis.py), thread the same logical shape through geometry creation, per-energy projection, `_native_indices`, both fused and unfused projection, cache keys and eviction. The current endpoint helper calls projection and eviction without a shape override. Preserve N for material arrays and FFT slice count. Record N, M, offset and `detector_grid_convention=fft_bins_v1` on detector and reduced results. Compare reduction of `N=1, M>1` to explicit B or signal that combination as unsupported. Qualify full-depth execution first. For unsupported configurations or capacity errors, signal the reason or complete the requested M on a verified alternate route. Exercise single energy, multiple angles and an allocation-fallback path.
4. **Measure through the normal public call.** Use the speed harness with `--path default` for A, recording the observed route in a separate `--stages` pass. Record C's distinct evaluator and target M. Use `--expect-route` when checking a route known to be selected. Keep optics, angles, dtype, window, input/result residency, output layout and GPU identical within a comparison. Start with the setup’s host-input/host-detector case. Also run with GPU-resident inputs to isolate compute. Use uninstrumented, synchronized wall times. Report first-call and warm times separately, A/A variation, alternating or interleaved paired samples (3 for screening, at least 5 for a decision), medians, C/A runtime ratio and B/C speedup. Collect `--stages` and `--memory` separately.

| Order | Cases | Comparisons |
|---|---|---|
| 1 | Small and medium grids with one energy/one E direction, then 20 energies/12 directions | A and B versus both C evaluators at pad factors 1, 2, 4 and 8. Include one noninteger ratio for the selected-sum control. |
| 2 | 128 × 1024² with the same two workloads | Measure A once per matched workload, C at M=128, 256, 512, 1024 and B at every feasible depth. Report speed and measured peak memory together. |
| 3 | 101 energies/12 directions on the maintained small fixture, then the largest matched feasible case | Reuse the occupied basis across energies. Record actual FFT counts, union size, per-energy projection cost, detector output and total time. |

Measure baseline, absolute and incremental process GPU peaks, host peak, largest allocations and FFT plan/workspace. Report the polling interval and allocator high-water marks where available. A 128 × 1024² FP32 scalar occupies 512 MiB and its slice RFFT occupies 513 MiB in complex64. A single 1024³ complex64 array occupies 8 GiB. Compare measured C scaling against B and A including all live basis and output buffers. If the full explicit cube exceeds available VRAM, record capacity or the failed allocation, compare B/C at the largest common size and check selected coefficients or columns at 1024 via a CPU oracle. Quote speedup only for matched sizes actually timed. A slower C can still qualify as an opt-in fidelity feature.

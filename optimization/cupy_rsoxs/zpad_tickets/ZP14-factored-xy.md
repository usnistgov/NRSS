# ZP14 · Compare exact lateral transforms on the required Fourier columns

**Question.** Can severe lateral oversampling of a small crop avoid enough padded-plane FFT work to beat the tuned ZP13 cuFFT route? The present `virtual_3d_sum` computes a logical 2D RFFT plane at full XY dimensions for each occupied slice. The CPU residue reference uses a different factorization. Screen both the arbitrary-shape route and one integer-ratio candidate, with end-to-end comparisons.

**First candidate, separable transforms.** For each real occupied slice (or a bounded slab of slices and basis rows):

1. Multiply by the existing logical XY window, cropped at the centered occupied indices, and form the material-fill contrast as on the parent. Run length-`Mx` 1D real FFTs on the **occupied** Y rows. Their output shape, before selection, is `(tile_z, occupied_y, Mx//2+1)`. This avoids first filling every logical Y row with zeros.
2. Canonicalize required native kx from the detector endpoint union plus DC neighbors. For a bounded group of needed kx, run length-`My` complex FFTs along the occupied Y data with zero extension to `My`. Gather only the requested ky for each kx and accumulate the required axial modes. Try a layout that keeps the 1D transform contiguous. Measure the conversion, gather/scatter, plan and scratch costs. X-first versus Y-first can differ on rectangular crops and targets.
3. Apply the full centered origin phase exactly once. For negative-half partners conjugate the real geometry basis and reflect **all three** native indices before mixing complex optics. Add the separable finite-box fill with the same window, apply the logical DC repair and use the unchanged endpoint-power interpolation. Symmetry of an isotropic sphere supplies no exemption from the off-axis tests.

This computation handles noninteger ratios. At 8192 the current full panel has 11.14 million valid pixels, but all required kx groups have to be serviced. Report how many half-plane columns and 1D transforms actually ran, as well as axial gathers, live scratch, logical FFT elements, and D2H bytes. Measure wall time and the fraction of actual transform work avoided. The included [CPU coefficient probe](../../../tests/validation/dev/cupy_rsoxs_virtual_3dpad/check_factored_xy.py) checks phase, reflection, exact signed bins, fill, window and DC at mixed-parity target sizes. Use it as a reference for this candidate. Collect cuFFT timings on the local GPU.

**Second candidate, integer-ratio residues.** For `M=rn` and `k=rℓ+s`, apply the `exp(-2πisj/M)` phase to occupied samples before the native `n`-point FFT and combine with the centered-placement phase. General lateral residues require complex transforms. Batch useful residue pairs or compare a one-axis hybrid. Count launches, batched work, permutations, angular support and occupancy. A 128→8192 XY pad has up to 4096 residue pairs, and most may intersect support despite the finite detector disk. Limit the prototype effort if dispatch costs dominate. The qualified [CPU sphere pilot](../../../tests/validation/dev/cupy_rsoxs_virtual_3dpad/residue_pilot.py) provides an independent integer-cube result.

**Acceptance.** A/B each candidate against the fastest exact incumbent from ZP13 and the pinned parent, starting at 1024/2048 before measuring 4096/8192. Include the 52→1024 noninteger vesicle and a rectangular mixed-parity target. Test both fills, manual XY windows, unwindowed Z, signed complex coefficients, complete masks and absolute detector intensities. Publish which shapes win, peak VRAM, first-call planning cost and crossover, including rejected variants. For losing shapes keep the qualified route. The algorithm can still be worth retaining for a clearly identified useful shape range.
